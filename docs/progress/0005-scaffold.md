# 0005 — Каркас проекта

- **Дата:** 2026-09-29
- **Ветка:** `chore/scaffold`
- **Статус:** готово
- **Инструменты:** Claude Opus 5 в Claude Code

## Задача

Поднять каркас: страница-заглушка и `/api/health`. API не прорабатывать — нужно, чтобы всё
запускалось.

## Что сделано

- Один `package.json`, Node ≥ 20.19. Скрипты: `dev`, `build`, `start`, `typecheck`.
- Vite + React 19 + TypeScript, строгий режим с `noUncheckedIndexedAccess`
  и `verbatimModuleSyntax`.
- `server/index.ts` — Express 5 на `tsx`: `GET /api/health`, JSON-404 на неизвестные
  маршруты под `/api`, раздача `dist/` и SPA-фолбэк в проде.
- Vite проксирует `/api` на :8787 — браузер ходит только на свой origin с самого начала.
- `.env.example`, раздел запуска в README.

## Принятые решения

- **Два `tsconfig` без project references.** Один на `src`, другой на `server` и `vite.config.ts`;
  `typecheck` прогоняет оба. Референсы потребовали бы `composite` и возни со сборочными
  инфо-файлами ради проекта из двух каталогов.
- **Прод запускается через `tsx`, а не через собранный JS.** Сборка сервера ради одного файла —
  лишний шаг в цепочке, который нечем оправдать на этом размере.
- **404 под `/api` отдаётся раньше SPA-фолбэка.** Иначе опечатка в пути к API вернула бы
  HTML со статусом 200, и ошибка всплыла бы уже в разборе ответа, далеко от причины.
- **Стилей нет совсем.** Токены Nocturne — первый пункт фазы 2; класть их в каркас значило бы
  начать фазу 2 в коммите про каркас.

## Где ИИ ошибся

- **Что предложила:** SPA-фолбэк как `app.get('*', …)` — привычная форма из Express 4.
  **Как заметили:** до запуска, при сверке с версией — в `package.json` стоит Express 5,
  а он разбирает пути через path-to-regexp v8, где голая `*` больше не валидна и бросает
  исключение на старте.
  **Как поправили:** фолбэк сделан обычным middleware в конце цепочки — работает и в 4, и в 5.

- **Что сделала:** первая проверка прода не дождалась старта сервера — цикл ожидания крутился
  без задержки и отработал мгновенно, `curl` получил пустоту. Выглядело как «сервер не поднялся».
  **Как заметили:** в логе сервера не было ни строчки об ошибке — значит, дело было
  не в сервере, а в проверке.
  **Как поправили:** `curl --retry --retry-connrefused`. Вывод на будущее: прежде чем чинить
  то, что «не работает», стоит убедиться, что сломано именно оно, а не проверка.

## Что осталось

Ничего по этой задаче. Дальше — фаза 1, мок-сервер.

## Как проверить

```bash
npm install
npm run dev          # :5173 показывает, что /api/health отвечает
curl -s localhost:5173/api/health   # {"status":"ok","uptime":…} — через прокси Vite
npm run preview      # сборка и прод-режим на :8787
```

Проверено: `npm run build` проходит, оба режима поднимаются, `/api/health` отвечает и напрямую,
и через прокси, неизвестный `/api`-маршрут даёт JSON-404, в проде `/` отдаёт `index.html`.

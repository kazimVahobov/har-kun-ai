# Отчёты о работе

Один файл на задачу. Пишет ИИ-агент, закончив задачу, — до того, как переключиться на следующую.

## Зачем

Задание требует в README честный ИИ-лог: какими инструментами пользовались, **где ИИ ошибся и как
это заметили и поправили**. Задним числом такое не восстанавливается: через три часа работы никто
не вспомнит, что модель сначала предложила `EventSource` для POST-запроса и это всплыло только
на первом запуске.

Либо записано по горячим следам, либо потеряно. На финальной фазе README собирается отсюда.

## Правила

- **Имя файла:** `NNNN-slug.md`, нумерация сквозная, четыре цифры: `0002-mock-server.md`.
- **Один файл на задачу**, не на день и не на фазу. Фаза из трёх задач — три файла.
- **Файл не переписывается задним числом.** Отчёт фиксирует, как было, а не как хотелось бы,
  чтобы выглядело аккуратно. Ошибся — так и остаётся записанным; исправление идёт следующим
  абзацем или следующим отчётом.
- **Шаблон** — `_template.md`. Поля не выкидывать: пустое «ИИ ошибся» лучше, чем отсутствующее,
  потому что видно, что вопрос задавали.
- **Писать конкретно.** «Была проблема со стримингом, починили» — бесполезная строчка.
  «Парсер терял событие, если чанк обрывался между `event:` и `data:` — поймали моком,
  который режет кадры» — то, ради чего файл существует.
- **Тупики и неудачные подходы — обязательно.** Отчёт «всё прошло гладко» по итогам работы,
  где что-то переделывалось, хуже, чем его отсутствие: он врёт.

# Har Kun

Чат с языковой моделью и потоковым выводом, сделанный как тестовое задание. React + TypeScript на
фронте, небольшой прокси на Express за ним — чтобы ключ OpenRouter не попадал в браузер. Ответ
появляется по мере того, как модель его пишет, и его можно оборвать на середине, не потеряв уже
полученное.

> Перевод английского [README.md](README.md) — для проверяющего, которому удобнее по-русски.
> Оригинал остаётся источником правды: при расхождении прав он.
>
> Интерфейс самого приложения на русском: задание пришло на русском и проверяться будет на русском
> ([ADR 0005](docs/adr/0005-no-localization.md)). Всё остальное, что видит разработчик — код,
> комментарии, коммиты, документация в `docs/`, — на английском.

## Запуск

Node ≥ 20.19 (собиралось и проверялось на 22).

```bash
npm install
npm run dev
```

Открыть <http://localhost:5173>.

**Работает вообще без ключа.** Без `OPENROUTER_API_KEY` сервер поднимается на моке, который
изображает живую модель — случайная длина и скорость, markdown, рваные кадры и отказы по запросу.
Весь интерфейс делался против него ([ADR 0003](docs/adr/0003-mock-first.md)), так что проверяющий
увидит всё в работе, не заводя аккаунт на OpenRouter.

Чтобы говорить с настоящей моделью:

```bash
cp .env.example .env     # и вписать свой ключ в OPENROUTER_API_KEY
npm run dev
```

Режим сервер определяет по одному этому — без ключа мок, с ключом OpenRouter — и говорит, какой,
при старте:

```
[server] development, OpenRouter, listening on http://localhost:8787
[models] live catalogue: 16 free models, default nvidia/nemotron-3-super-120b-a12b:free
```

`MOCK=1` заставляет использовать мок даже при наличии ключа; `MOCK=0` без ключа — это сервер,
который отказывается стартовать и объясняет почему, вместо сервера, который выглядит здоровым и
падает на первом же вопросе.

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Vite на :5173, бэкенд на :8787, `/api` проксируется |
| `npm test` | Vitest — 164 теста |
| `npm run build` | сначала проверка типов, потом сборка в `dist/` |
| `npm start` | продакшен: один процесс отдаёт и `dist/`, и `/api` |
| `npm run typecheck` | только типы, клиент и сервер |

Всё, что настраивается, описано в [`.env.example`](.env.example).

## Что умеет

- **Потоковый вывод** по SSE: текст появляется по мере генерации.
- **Стоп** — кнопкой или `Esc`. Полученная часть остаётся в истории, интерфейс живой, следующее
  сообщение отправляется сразу.
- **Любой отказ заканчивается состоянием, которое можно прочитать** — 429 с обратным отсчётом,
  если сервер сверху назвал время, таймауты, обрыв связи, ошибка посреди ответа. Ни вечного
  спиннера, ни выброшенного частичного ответа.
- **История в рамках сессии**, восстанавливается после перезагрузки.
- **Клавиатура целиком** — Tab, Enter отправляет, Shift+Enter переносит строку, Esc останавливает;
  ссылка перехода к полю ввода, семантичная разметка, одна вежливая живая область.
- **Markdown** в ответах, рендерится на лету, с закрытием незакрытых блоков кода перед разбором.
- **Выбор бесплатной модели** из живого каталога OpenRouter, отфильтрованного по `:free`.

## Ключевые решения

Шестнадцать решений записаны в [`docs/adr/`](docs/adr/) вместе с контекстом и ценой. Те, что
сильнее всего повлияли на код:

**Ключ живёт только на сервере** ([ADR 0002](docs/adr/0002-api-key-on-server.md)). Читается из
`process.env` внутри `server/` и оттуда не выходит. Браузер обращается только к своему origin.
Стоит назвать ловушку, которую это обходит: `import.meta.env` с префиксом `VITE_` — это одна
строка, и она **вшивает значение в бандл**, то есть ровно туда, откуда задание просит его убрать.
`grep` по собранному `dist/` не находит ни `openrouter`, ни `Bearer`.

**Своя форма SSE вместо проброса апстрима**
([ADR 0009](docs/adr/0009-normalized-sse.md)). HTTP не может поменять статус после того, как
заголовки ушли, — значит ошибка, случившаяся после первого токена, не может быть 502, она обязана
стать событием внутри 200. Поэтому в контракте две формы ошибки, и решение, какая применима,
принадлежит серверу. Проброс OpenRouter насквозь отдал бы это решение клиенту.

**Мок появился первым и остался** ([ADR 0003](docs/adr/0003-mock-first.md)). 429 от бесплатной
модели приходит когда придёт; обрыв связи надо ставить руками. `?simulate=` превращает каждое
такое состояние в один URL. Цена — контракт, который приходится записать и держать
синхронизированным между двумя реализациями; поэтому он лежит в [`docs/plan.md`](docs/plan.md), а
не только в коде.

**История переживает перезагрузку и умирает вместе со вкладкой**
([ADR 0008](docs/adr/0008-session-storage-history.md)). Задание оставляет выбор за нами, значит —
`sessionStorage`. Разговор с моделью контекстен: почти вся его ценность внутри сессии, пока человек
решает задачу. Через неделю это шум, который никто не перечитывает, но он лежит в браузере, куда
могут заглянуть другие. `sessionStorage` проводит границу там, где она уже проходит у пользователя
в голове: случайный F5 ничего не стоит, закрытая вкладка уносит всё, и не надо придумывать,
объяснять и помнить кнопку «очистить историю».

Сообщение, застигнутое посреди потока, восстанавливается как **остановленное**, а не как
пишущееся, — иначе после перезагрузки индикатор печати крутился бы для потока, которого больше нет.
Запись отложена во времени, чтение обёрнуто: приватный режим и переполненная квота бросают
исключение, а чат не должен умирать из-за своей истории.

**Список моделей запрашивается, а не зашит**
([ADR 0016](docs/adr/0016-free-model-catalogue.md)). В каталоге на момент разработки было 460
моделей, 16 из них бесплатные, и ни одна из шестнадцати не обещает остаться бесплатной через
месяц. Зашитый список устареет раньше, чем проект кто-то запустит, и откажет он худшим из
возможных способов: список выглядит нормально, а каждая модель в нём отвечает 404.

**Всё визуальное приходит из токенов** ([ADR 0004](docs/adr/0004-single-dark-theme.md),
[`docs/design-system.md`](docs/design-system.md)) — одна тёмная тема, без переключателя, без hex и
без пикселей вне шкалы. У ошибок нет своего цвета: иконка, заголовок и текст — то, что переживает
дальтонизм и скринридер.

## Пушбек: `outline`

Задание просит двух вещей, которые нельзя выполнить буквально одновременно.

> Доступность: интерфейсом можно полноценно пользоваться с клавиатуры — Tab по элементам, Enter
> отправляет, Esc останавливает генерацию.

> Уберите стандартную браузерную обводку фокуса (`outline`) у кнопок и поля ввода — в разных
> браузерах она выглядит разнобойно и портит аккуратный вид.

Обводка фокуса — единственное, что показывает, где ты находишься при навигации с клавиатуры. Убери
её, и Tab идёт вслепую: нажимая Enter, отправляешь то, чего не видишь. Второе требование,
выполненное по букве, отменяет первое.

При этом диагноз в нём верный: стандартная обводка действительно выглядит по-разному везде.
Проблема в предложенном лекарстве.

**Поэтому выполнен смысл, а не буква.** Браузерной обводки нет; вместо неё каждый интерактивный
элемент несёт свою собственную, одинаковую во всех браузерах и заданную дизайн-системой:

```css
:focus         { outline: none; }
:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; }
```

`:focus-visible` — ровно то различение, которого не хватало формулировке: нет обводки при клике
мышью, есть при навигации с клавиатуры. Аккуратный вид сохранён для мыши, клавиатурный путь не
сломан. Поле ввода вместо второй обводки подсвечивает рамку — оно уже обрамлено.

Полное рассуждение в [ADR 0007](docs/adr/0007-custom-focus-ring.md). Оно вынесено сюда, а не
оставлено на самостоятельное обнаружение, потому что проверяющий, читающий требование буквально,
иначе засчитал бы его невыполненным.

## Бюджет времени, который не выдержан

Задание просит уложиться в два-шесть часов чистого времени. Ушло **восемь-девять** — продумывание
идеи, документы и код вместе. Это перебор, и достаточный, чтобы округлять его вниз было
увиливанием; поэтому он здесь, а не запрятан в отчёте.

Куда они ушли, видно по репозиторию: шестнадцать записей о решениях, семнадцать отчётов о ходе
работы, написанная дизайн-система, спецификация экрана. Часть этого запросило само задание — оно
оценивает процесс и хочет ИИ-лог с тем, где модель ошиблась и как это заметили. Такое не
восстанавливается задним числом: либо пишется по ходу, либо теряется, и
[один отчёт, написанный поздно](docs/progress/0017-readme.md), показывает, чего стоит
реконструкция.

Но это объясняет часть, а не всё. Остальное — объём, который я выбрал сам: рейл оглавления
([ADR 0015](docs/adr/0015-contents-rail.md)), шкала дня и работа над идентичностью вокруг неё
([ADR 0013](docs/adr/0013-typography.md), [ADR 0014](docs/adr/0014-opens-on-the-day.md)), выбор
модели. Каждое обосновано в своей записи, и ни одного из них нет в `TASK.md`. Сайдбар — тот
единственный кусок самоназначенной работы, который остановили до того, как он был построен
([ADR 0012](docs/adr/0012-chat-sidebar-scope.md)); суждение, поймавшее его, должно было достать и
до остальных трёх.

Если жёстко держать шесть часов, первыми уходят эти три, в том же порядке, а письменная часть
сжимается до плана, контракта и отчётов — без прописанной прозой дизайн-системы, без записи для
решения, которое никто не стал бы оспаривать. Уцелеть при сокращении обязаны функциональные
требования и края: стриминг, стоп, состояния отказа, ключ на сервере. Это же и то, что задание
называет первым критерием оценки, и то, чем я не стал бы жертвовать ради всего перечисленного выше.

## Проверка краевых случаев

Мок воспроизводит по требованию то, что бесплатная модель выдаёт только по случайности. Вне
продакшена `POST /api/chat` принимает `?simulate=`:

| Значение | Что происходит |
|---|---|
| `429` | лимит до начала потока, с `Retry-After` |
| `timeout` | соединение держится, первый токен не приходит |
| `drop` | соединение умирает посреди потока, без `done` |
| `mid-error` | часть ответа, затем событие `error` |
| `slow` | 300–800 мс между кусками |

```bash
curl -sN -X POST 'localhost:8787/api/chat?simulate=mid-error' \
  -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"hi"}]}'
```

Сторож первого токена по умолчанию 30 с; чтобы посмотреть, как он срабатывает, укоротите:
`TIMEOUT_FIRST_TOKEN_MS=2000 npm run dev:server`.

С настоящим ключом те же состояния приходят сами. Все шестнадцать бесплатных моделей были опрошены
одним вопросом: пять ответили примерно за секунду, три упёрлись в лимит общего пула, две оказались
доступны только определённым приложениям, одна была недоступна, ещё одна вернула заголовки, но так
и не прислала ни одного токена.

## ИИ-лог

Написано Claude Opus 5 в Claude Code под человеческим ревью, примерно за сутки календарного
времени, мелкими коммитами на десяти рабочих ветках — девяносто на момент написания. Проверки в браузере — через Chrome-автоматизацию
Claude; другого инструментария здесь нет.

Честная версия «как оно шло» лежит в [`docs/progress/`](docs/progress/) — семнадцать отчётов, по
одному на задачу, в каждом обязательный раздел о том, где ИИ ошибся. Шестнадцать написаны по ходу
работы, потому что задним числом это не восстанавливается;
[семнадцатый](docs/progress/0017-readme.md) написан поздно, для фазы, которая обошлась без отчёта,
и начинается с признания, чего это ему стоило. Ниже — сводка; подробности в файлах.

### Где оно пошло не так и как это всплыло

**Уверенный код, который ломается только под нагрузкой.** `runChatStream` полагался на то, что
`fetch` разберёт тело ответа, когда сработает сигнал отмены. Он этого надёжно не делает. Четыре
теста зависли до таймаута — прогон вырос со 120 мс до 20 с, так это и заметили. Починено явной
отменой ридера. Тот же урок потом был *применён*, а не выучен заново, когда писался адаптер
OpenRouter ([0010](docs/progress/0010-chat-streaming.md),
[0014](docs/progress/0014-openrouter.md)).

**Одна утилита, три дефекта, один корень.** `.visually-hidden` использовал обычный рецепт с
`position: absolute`. Он вылезал из прокручиваемого лога и давал окну собственную полосу прокрутки;
он выделялся, поэтому копирование ответа вставляло скрытую подпись автора «Модель» в следующий
вопрос; а как строчный `<label>` он игнорировал `height` и тихо раздувал композер. Каждый нашли
отдельно, глазами, в браузере. «Спрятать визуально, оставить доступным» — это не одно свойство, а
набор ограничений, и каждое всплывает в своём контексте
([0011](docs/progress/0011-styled-ui.md), [0013](docs/progress/0013-ui-refinement.md)).

**API, использованный по неверной ментальной модели.** Рейл оглавления следил за текущим вопросом
через `IntersectionObserver`, который сообщает об *изменениях* пересечения, — и при длинном ответе
во весь экран полосу никто не пересекал, рейл продолжал указывать на первый вопрос, пока виден был
шестой. Заменено прямым измерением. Первая замена была прижата к `requestAnimationFrame`, из-за
чего переставала работать в фоновой вкладке, где rAF не выполняется
([0013](docs/progress/0013-ui-refinement.md)).

**Ожидания в тестах, написанные из того, что хотелось увидеть.** Четыре раза — дважды на обработке
`\r` в SSE-парсере, один раз на сортировке по свежести с зашитым временем, один — на том, где
`summarise` ставит границу слова. Каждый раз код был прав, а ожидание — нет. Самая повторяющаяся
ошибка в логе ([0007](docs/progress/0007-sse-parser.md),
[0008](docs/progress/0008-chat-reducer.md), [0013](docs/progress/0013-ui-refinement.md)).

**Тест, закодировавший то же заблуждение, что и код.** 401 и 403 были сведены в одну ветку — «ключ
сломан» — с юнит-тестом, это утверждающим. OpenRouter отвечает 403 ещё и для модели, доступной
только определённым приложениям, где с ключом всё в порядке, — и интерфейс сообщал пользователю,
что сервер настроен неправильно, не давая ему ничего, что он мог бы сделать. Тест поймать это не
мог; настоящий 403 появился только при опросе всех шестнадцати бесплатных моделей живым ключом
([0014](docs/progress/0014-openrouter.md)).

**Погоня за багом, которого не было.** Повтор запроса будто бы срабатывал сам, дважды. Я поднял
чистое состояние, воспроизвести не смог и сказал об этом, вместо того чтобы придумать объяснение.
Ответ нашёлся, когда владелец спросил, что происходит при нажатии «Повторить»: браузер был его, и
нажимал он. Урок не в том, что «надо учитывать пользовательский ввод», — он в том, что
невоспроизводимой аномалии не полагается *никакого* объяснения, пока она не воспроизведётся
([0013](docs/progress/0013-ui-refinement.md)).

**Симптом лечили дважды, прежде чем увидели причину.** «Enter — отправить» стояла рядом с кнопкой
отправки и исчезала на узких экранах. Сначала её сдвинули влево и закрепили от сжатия; и только
когда перестроили весь ряд, стало ясно, что подсказке вообще не место внутри этого ряда. Если
элементу нужен `flex: 0 0 auto`, чтобы его не раздавили, — это признак того, что он не в том
контейнере, а не того, что ему нужно правило посильнее
([0015](docs/progress/0015-ui-fixes.md)).

**Чуть не написал список бесплатных моделей по памяти.** В плане жирным было сказано: читать
каталог в момент реализации. Чтение вернуло 460 моделей и 16 бесплатных — и ни одного из
идентификаторов, которые я написал бы по памяти, среди них не оказалось
([0014](docs/progress/0014-openrouter.md)).

**Правила, которым код не мог подчиниться, написанные той же моделью, которая их потом нарушила.**
Финальная сверка с `TASK.md` прочитала инструкции для агентов рядом со стилями и нашла два пункта,
которым не удовлетворяло ничто в проекте: один требовал `:focus-visible` рядом с каждым
`outline: none` — а поле композера вместо этого подсвечивает рамку вокруг себя, и это лучшее
решение, — второй требовал токен для каждого пикселя, в дизайн-системе, где токенов размера нет
вообще, а слой компонентов перенесён вместе со своими литералами. Правило, которое нарушает каждый
файл, — не правило. Оба переписаны под то, что проект действительно делает, а единственное
настоящее нарушение, прятавшееся среди ложных — `#000` в маске, — получило имя
([0016](docs/progress/0016-assignment-audit.md)).

Тот же проход нашёл зависимость, которую никто не импортирует, оставшуюся после решения, её
заменившего; ключ хранилища, который ADR всё ещё называл по-старому; инструментарий агента,
закоммиченный внутри постороннего коммита по интерфейсу; и прокси дев-сервера, который молча
игнорировал `PORT`, пока `.env.example` утверждал обратное. Ничто из этого не ломает демо. Всё это
— то, что замечает только читатель, сличающий два файла, и написала это всё модель.

**И то, что вообще не было багом в коде.** Выбор моделей продолжал показывать моковые, пока лог
старта говорил `OpenRouter`. Один процесс не может делать и то и другое — и это противоречие и было
всем диагнозом: работали два стека `npm run dev`, и порт занял тот, что постарше, запущенный до
того, как в скрипт добавили чтение `.env`. Ответил список процессов; перечитывание обработчика не
ответило бы ([0014](docs/progress/0014-openrouter.md)).

### В чём ИИ был хорош, честно

В написании SSE-парсера против границ чанков и тестов, режущих кадр на каждой байтовой позиции. В
удержании контракта синхронным в двух реализациях. В производстве записей о решениях вместе с их
ценой. Человек же требовался раз за разом для одного — **смотреть на экран**: почти все дефекты
выше были невидимы для проверки типов и для тестов, и каждый нашёл человек, показавший пальцем и
сказавший, что вот это неправильно.

## Что дальше, будь ещё день

В том порядке, в каком я бы этим и занялся:

1. **Как следует проверить 320px.** Это единственное требование, которое я не могу заявить.
   Браузерная автоматизация рапортует об успешном изменении размера, пока вьюпорт остаётся 1512, —
   значит, адаптивную вёрстку смотрели только чтением CSS и сжатием контейнеров, а это проверяет
   поведение flex, а не медиазапросы. Нужно настоящее устройство или драйвер, который правда меняет
   размер.
2. **Компонентные тесты для состояний, которые ломаются регулярно.** Редьюсер, парсер и раннер
   потока покрыты хорошо; всё, что ловило ревью, живёт в слое рендера и не покрыто ничем. Горсть
   тестов вокруг состояний сообщения и композера поймала бы как минимум пустой блок ответа.
3. **Свести два цвета границы.** `--color-divider` полупрозрачный, поэтому один и тот же токен
   выглядит по-разному на ответе и на композере, которые лежат на разных подложках; а карточка
   ошибки рисует свой кант через `--shadow-sm`, то есть токеном высоты вместо токена разделителя.
   И то и другое известно и оставлено сознательно, а не проглядено.
4. **Сайдбар чатов.** Несколько разговоров с переключением между ними, генерация продолжается в
   фоне. Спроектирован и сознательно отложен — `TASK.md` нигде не просит больше одного чата, и
   сборка сайдбара была бы объёмом, который я выбрал за проверяющего, а не работой, о которой он
   просил ([ADR 0012](docs/adr/0012-chat-sidebar-scope.md)).
5. **Задеплоить** ([ADR 0010](docs/adr/0010-deployment.md)). Домен ждёт; сервер уже и так один
   процесс, отдающий `dist/` и `/api`.
6. **Аккаунты и собственный ключ.** Сначала вход через Google — один провайдер, и ничьих паролей
   хранить не надо, — а затем то, ради чего он и нужен: аккаунт может прицепить свой ключ
   OpenRouter, и его запросы тратят именно его. Шестым, а не первым, потому что необходимым это
   делает деплой: на публичном адресе каждый посетитель тратит бесплатную квоту владельца, и первый
   же 429 общий.

   Это же и самый крупный пункт здесь, и он сдвигает два уже принятых решения. Чужой ключ надо
   шифровать при хранении, и он не должен возвращаться в браузер —
   [ADR 0002](docs/adr/0002-api-key-on-server.md) снова, но с таким числом ключей, сколько
   аккаунтов, а это другая задача, чем хранить один. А как только появляются аккаунты, истории
   место на сервере, и [ADR 0008](docs/adr/0008-session-storage-history.md) пришлось бы
   пересматривать: `sessionStorage` был выбран для однопользовательского приложения, которому
   разговор просто некуда больше положить. [`docs/plan.md`](docs/plan.md) уже числит аутентификацию
   вне объёма задания и обещает, что запись будет здесь, — вот она.

Мельче, для честности: `Esc — остановить` показывается в карте клавиш, даже когда ничего не
генерируется; и «Повторить» предлагается только у последнего сообщения, поэтому у такой же карточки
ошибки выше по разговору кнопки нет.

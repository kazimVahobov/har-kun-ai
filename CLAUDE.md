# CLAUDE.md

Инструкции для ИИ-агентов, работающих в этом репозитории.

## Что это за проект

Одностраничный веб-чат с языковой моделью. Тестовое задание на вакансию фронтенд-разработчика.

**`TASK.md` — первоисточник требований.** Он главнее этого файла, плана и любых пересказов.
Если видишь расхождение — прав `TASK.md`, а расхождение нужно озвучить, а не замять.

Читать перед тем, как писать код:

- `docs/plan.md` — план работ по фазам и контракт API.
- `docs/ui-structure.md` — раскладка экрана, элементы, состояния, клавиатура.
- `docs/design-system.md` — дизайн-система Nocturne: токены, компоненты, перенос на чат.
- `docs/adr/` — принятые решения с контекстом и последствиями.

## Стек

Один `package.json` на весь проект.

| Слой | Чем |
|---|---|
| Фронт | Vite + React + TypeScript |
| Стили | чистый CSS + CSS Modules, CSS custom properties |
| Бэк | Express, запуск через `tsx` |
| Тесты | Vitest |

Структура:

```
server/     прокси: /api/chat (SSE), /api/models. Здесь и только здесь живёт ключ
src/        React-приложение
  lib/      чистая логика: парсер SSE, редьюсер чата, storage — сюда же тесты
docs/       план и отчёты о работе
```

## Железные правила

Это не стилистика, это то, что ломает задание при нарушении.

1. **`OPENROUTER_API_KEY` не покидает `server/`.** Ни в бандл, ни в `import.meta.env`, ни в ответы
   API, ни в логи, ни в сообщения об ошибках. Задание проверяют вкладкой Network — браузер ходит
   только на свой origin.
2. **`.env` не коммитится.** Никогда, ни под каким предлогом. В репозитории живёт только
   `.env.example` с плейсхолдерами.
3. **`outline: none` без парного `:focus-visible` — запрещён.** Задание просит убрать браузерную
   обводку и в том же документе требует полноценную работу с клавиатуры. Выполняем по смыслу:
   дефолтную обводку снимаем, но каждый интерактивный элемент получает собственное видимое кольцо
   через `:focus-visible`. Подробнее — в `docs/plan.md`, раздел «Пушбек».
4. **Мок и реальный адаптер живут за одним контрактом.** Контракт описан в `docs/plan.md`.
   Меняешь контракт — меняешь обе реализации и документ, в одном коммите. Разъехавшийся контракт
   обнаружится только на этапе подключения живой модели, то есть поздно.
5. **Спиннер не бывает вечным, частичный ответ не теряется.** Любой исход генерации — успех,
   остановка, ошибка, таймаут, обрыв — переводит сообщение в финальное состояние и оставляет
   уже полученный текст в истории.
6. **Разметка семантическая.** `<main>`, `<ol>`/`<li>`, `<form>`, `<label>`, `<button>`.
   Не `div` с `onClick`.
7. **Никаких значений мимо токенов.** Ни хекса, ни названия шрифта, ни пикселя, который уже
   несёт шкала Nocturne, — только `var(--color-*)`, `var(--space-*)`, `var(--radius-*)`,
   `var(--shadow-*)`, `var(--font-*)`. Не хватает токена — это не повод вписать число,
   а повод добавить расширение и описать его в `docs/design-system.md`.
8. **Каталог `nocturne/` не коммитить.** Это локальный бандл дизайн-системы, исключённый
   через `.git/info/exclude`. **В `.gitignore` его тоже не добавлять** — `.gitignore`
   попадает в репозиторий. Источник правды по токенам для кода — `docs/design-system.md`,
   он самодостаточен и работает без бандла.

## Процесс

- **Ветка на фазу**, имя вида `feat/mock-server`, `feat/ui`, `docs/readme`.
- **Коммиты по ходу, осмысленными шагами.** Один коммит «done» на всю фазу — прямо названный
  в задании красный флаг.
- **Все сообщения коммитов — на английском.** Кратко, в повелительном наклонении:
  `add SSE parser`, `handle abort in mock stream`. Документы, комментарии в коде и общение —
  по-русски; коммиты — нет, без исключений.
- **PR пользователь делает вручную. Агент их не создаёт и не мерджит.**
  `gh pr create`, `gh pr merge`, `git push` в `master` — не запускать. Даже если кажется, что фаза
  закончена и всё очевидно. Дело агента — ветка и коммиты в ней; дальше слово за пользователем.

## Отчётность

Закончил задачу — пиши отчёт в `docs/progress/` по шаблону `_template.md`. Правила — в
`docs/progress/README.md`.

Это не формальность. Задание требует в README честный ИИ-лог: какими инструментами пользовались,
**где ИИ ошибся и как это заметили и поправили**. Задним числом такое не вспоминается — либо
записано по горячим следам, либо потеряно. README на финальной фазе собирается из этих файлов.

Писать честно, включая тупики и неудачные подходы. Отчёт «всё прошло гладко» по итогам работы,
где что-то переделывалось, — бесполезен.

## Чего не делать

- Не редактировать `TASK.md` — это присланный текст задания, он неприкосновенен.
- Не добавлять зависимости без необходимости. Каждая новая — решение, которое нужно обосновать
  в отчёте. Задание оценивает вкус, а не умение ставить пакеты.
- Не расширять объём молча. Увидел, что стоило бы сделать сверх задачи, — допиши в «что дальше»,
  а не реализуй по дороге.
- Не выдавать незавершённое за готовое. Не успел — так и напиши, это нормальный исход
  по условиям задания.
